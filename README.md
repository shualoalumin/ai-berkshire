# Value Council

**A four-analyst council for value investing research, built as a Claude Code plugin.**

Four analysts study the same business through four incompatible lenses — Buffett, Munger,
Graham, Lynch — and then argue with each other. Where they disagree and cannot be
reconciled on the evidence, the report says so instead of averaging the disagreement away.

Most research tools produce a number. This one produces a map of what is known, what is
contested, and what evidence would settle the contest.

---

## Install

```
/plugin marketplace add shualoalumin/value-council
/plugin install value-council@value-council
```

Skills are then available as `/value-council:council`, `/value-council:checklist`, and so
on.

Optional: set `FRED_API_KEY` (free, from the St. Louis Fed) to enable macroeconomic data.
The other two data connectors need no key.

## The skills

| Skill | What it does |
|-------|--------------|
| `/council` | The full four-lens review with structured cross-examination. Start here. |
| `/deep-dive` | Single-analyst comprehensive research, seven sequential modules |
| `/checklist` | Pre-purchase gate — seven checks, designed to stop early |
| `/screen` | Narrow a universe to a short list, exclusions first |
| `/thesis` | Write a thesis with sell conditions defined *before* buying, then track it |
| `/earnings` | Read the filing rather than the press release |
| `/management` | Judge capital allocation on the record, in numbers |
| `/portfolio` | Review holdings as one system — concentration and hidden correlation |
| `/pulse` | Triage a sharp price move; usually concludes "no action" |
| `/data-standards` | Sourcing rules every other skill follows |

## Design principles

**Disagreement is preserved.** Four ratings are reported as four ratings. Averaging
5/2/1/5 into a 3.25 destroys exactly the information the spread carried.

**The gate is meant to stop you.** Most companies fail the checklist, and they fail it
early. A checklist that passes everything is decoration.

**Sell conditions are written before buying.** Decisions made without a position are
better than decisions made with one.

**Silence beats speculation.** "Insufficient evidence" is a finding. A framework filled
in with plausible-sounding guesses looks like analysis and is worse than a blank page.

**Every judgment goes in the ledger.** `scripts/ledger.py` scores past calls against what
actually happened, including the wrong ones. A process that never checks its own output is
indistinguishable from one that produces nothing.

## Data

Three MCP connectors are wired in `.mcp.json`:

| Connector | Provides | Key |
|-----------|----------|-----|
| `sec-edgar` | 10-K, 10-Q, 8-K, XBRL facts, full-text search | none |
| `yahoo-finance` | Quotes, history, statements, estimates | none |
| `fred` | 800k+ macroeconomic series | free `FRED_API_KEY` |

Primary filings outrank everything else. Every material figure needs two independent
sources, and gaps above 1% are reported rather than silently resolved — see
`skills/data-standards.md`.

Arithmetic runs through `tools/rigor.py` in exact decimal, never in prose:

```bash
python3 tools/rigor.py market-cap --price 178.50 --shares 1.52e9 --reported 271.3e9
python3 tools/rigor.py scenarios  --price 178.50 --eps 8.42 \
    --growth 0.03 0.08 0.14 --exit-pe 12 18 25
```

## Repository layout

```
skills/              ten skills, registered as plugin commands
tools/rigor.py       exact decimal arithmetic for valuation
scripts/check.py     repository consistency gate — run before committing
scripts/ledger.py    scores past judgments against outcomes
memory/decisions/    per-company decision history (gitignored by default)
research/            your report output (gitignored by default)
docs/VISION.md       where this is going
```

## Contributing

```bash
python3 scripts/check.py
```

Must pass before any commit. It verifies manifest consistency, catches skills that exist
but were never registered, and enforces that the repository stays English-only.

## Status

Early. The skills are complete and usable; the track record is not yet built. There are
no performance claims here and there will not be any until `scripts/ledger.py` has scored
enough real judgments over enough time to mean something — at which point the results get
published whichever way they came out.
