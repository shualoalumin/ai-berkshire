# 决策记忆（Decision Memory）

参考 TradingAgents 的"持久化决策日志 + 回顾"模式重新实现：每次团队分析或实盘交易的
论文与结果都被记录，供未来分析时检索，形成"记得上次判断"的学习闭环——而不是每次
从零开始分析同一家公司。

## 为什么需要这个

没有记忆的分析流程会重复犯错：
- 半年前判断"护城河在变宽"，现在又重新论证一遍，却没检查半年前的判断是否兑现
- 已经因为"估值太贵"放弃过一次的公司，下次遇到又重新纠结一遍同样的问题
- 实盘交易的结果（赚了/亏了/为什么）没有反馈回研究流程

`memory/decisions/` 是这个反馈回路的存储层。

## 文件结构

```
memory/decisions/
├── README.md              — 本文件，记忆规范
├── {公司名}.md             — 每家公司一个记忆文件，追加式写入
└── ...
```

## 记忆文件格式

每个 `{公司名}.md` 是**追加式日志**，最新记录在最上面。每条记录包含：

```markdown
## {YYYY-MM-DD} · {来源 skill}

**综合评分**：X/5
**核心结论**：一句话

**关键分歧点**（如来自 investment-team 的结构化交锋）：
| 分歧点 | 多方论据 | 空方论据 | 裁决 |
|--------|---------|---------|------|

**核心假设**（如已建立 thesis）：
1. ...
2. ...

**后续验证**（下次分析时必须回填）：
- 上次判断 "___" → 本次证据显示：成立 🟢 / 弱化 🟡 / 受损 🔴 / 破裂 ⚫

---
```

## 写入时机

| 触发 | 写入方 | 内容 |
|------|--------|------|
| `/investment-team` 完成分析 | investment-team skill 第十一步 | 综合评分、结论、交锋记录 |
| `/thesis-tracker` 建立论文 | thesis-tracker skill A5 | 核心假设、红线清单 |
| `/thesis-tracker` 季度追踪 | thesis-tracker skill B7 | 假设验证状态、健康度评分 |
| 实盘交易发生 | 手动或 `/thesis-tracker` | 引用 `实盘记录/实盘操作记录.md` 对应行 |

## 读取时机（检索规范）

任何分析类 skill（`investment-team`、`investment-research`、`thesis-tracker`、
`news-pulse`）在开始分析某公司前，**先检查 `memory/decisions/{公司名}.md` 是否存在**：

- 存在 → 读取最新 1-2 条记录，在分析简报中注明"上次结论 + 距今时间 + 需重点回应的变化"
- 不存在 → 正常从零分析，分析完成后创建该文件

**核心原则**：记忆不是用来偷懒复制上次结论，而是用来**强制回答"什么变了"**——
如果半年后重新分析一家公司，结论和半年前一模一样却没有新证据支撑，这本身就是危险信号
（说明分析是在做重复劳动而非真正跟踪变化）。

## 与 `实盘记录/` 和 `reports/{公司}/{公司}-thesis.md` 的关系

三者分工不同，互不替代：

| 目录 | 内容 | 更新频率 |
|------|------|---------|
| `memory/decisions/{公司}.md` | **研究团队的历史判断**（评分、分歧、结论） | 每次跑分析类 skill |
| `reports/{公司}/{公司}-thesis.md` | **投资论文**（假设、红线、卖出条件） | 建仓时建立，每季度追踪 |
| `实盘记录/实盘操作记录.md` | **真实交易流水**（价格、股数、金额） | 每次实际下单 |

`memory/decisions` 是"AI 记得什么"，`thesis.md` 是"我为什么买/怎样算错"，
`实盘记录` 是"我实际做了什么"。三者共同构成买入前研究 → 买入决策 → 买入后纪律
→ 下次研究复用的完整闭环。
